*Doubao-Seed-Realtime-1.0在豆包实时语音模型 3.0（全双工Seeduplex）基础上，新增视频帧 / 图片输入与火山搜图能力，支持客户端将摄像头 / 屏幕画面以不超过 2 FPS 的频率推给服务端，模型结合画面进行对话。
*主要差异项：
*该版本 ASR 事件与客户端状态机完全解耦：ASR 事件只用于把用户识别文本展示给用户看（字幕、纪要），不能根据 transcription.completed 等ASR下行事件启停播放器。播放状态切换只需关注新增下行事件Response的状态，即 response.created / response.canceled / response.done。
*接入必读
*接入前请务必先完整阅读《接入必读》，了解协议设计原则、注意事项与最佳实践等，避免因协议不熟悉导致接入异常
*客户端状态机
*该版本客户端只需维护两个状态，状态切换完全由服务端下行事件驱动，不要再根据 ASR 事件本地推断。即：客户端维护一个枚举状态 LISTENING / SPEAKING；收到 response.created 置 SPEAKING，收到 response.canceled 或 response.done 置LISTENING。收到 response.canceled 时必须同步清空播放器缓冲，避免旧音频继续外放。

*session.created

*Session

*说明

*事件名

*类别

*rateint
*指定输入音频采样率，仅支持16000，单位为Hz

*rolestring
*指定对话角色，可选值user、assistant

*typestring
*指定输入音频格式，支持pcm和speech_opus

*call_id string
*函数调用的唯一标识，用于回传函数调用结果，须与下行事件response.function_call_arguments.done下发的call_id 保持一致

*frame_rate string
*视频帧率上限为 2 FPS，客户端不可调高；超过 2 FPS 的帧由网关限流丢弃。

*instructionsstring
*系统提示词（System message），用于引导模型的回复内容与音频风格，与模型内部 SP、对话历史上下文及FC结果合计长度上限为 64K tokens（系统提示词 instructions + 模型内部 SP + 对话历史上下文 + FC结果）

*event_idstring
*客户端发起请求时，可生成并传入自定义event_id，该字段为可选，建议传入，用于后续事件匹配与追踪
