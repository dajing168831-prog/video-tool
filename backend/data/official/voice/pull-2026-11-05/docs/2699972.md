*说话人分离是语音识别的重要能力之一，用于在多人对话场景中区分不同说话人，让每一句话都能标注"是谁说的"。当前支持两类产品形态：
*AUC（录音文件识别）：适用于已有录音文件的离线识别，提供大模型 SSD 标准版、长音频版-200（非会议场景）、长音频版-300（会议场景，效果最优）、声纹匹配版共 4 个版本，可覆盖短音频、长音频、2 人对话、多人会议等场景
*SAUC（流式语音识别）：适用于实时说话+边说边出字的场景，提供流式 SSD（实时分离）、流式 SSD 二遍（更高准确率）、短音频声纹识别（单说话人判定）共 3 个版本
各版本适用的音频时长、使用场景和调用方式有所不同，本文档汇总了各版本的核心参数、调用示例与选型建议，帮助您快速匹配合适的说话人分离方案
*版本总览
**
*注意
*enable_speaker_info=true 是启用说话人分离功能的开关参数；开启 enable_speaker_info 后，必须同时将 show_utterances 参数设置为 true，响应结果中才会返回包含说话人标识（speaker_id）的 utterances 分句列表，否则无法获取到说话人分离结果。下文所有调用示例均已包含该参数，请在接入时务必一并配置
*AUC各版本详细说明
*大模型标准版（ssd_version = "200"，普通模式）
版本说明：
*基于支持说话人分离的400中英文模型，通过模型能力结合 embedding 和聚类实现说话人分离
*聚类阈值为 1，对于长音频可能聚类出较多 speaker（不适用长音频）
调用方式：
 
*language 不指定或指定为 "zh-CN"（采用默认中英文模型）
*ssd_mode 不传或传 0 即为普通模式（默认）
*必须同时设置 show_utterances=true，才能在返回结果的 utterances 字段中拿到每个分句对应的 speaker_id
适用场景：
*短音频（3分钟以内）
*单一说话人语音较短（<5秒）的场景
*2人对话场景效果最优
*5人以内可用性较高
涉及链路： AUC 标准版 1.0 / 2.0 标准链路
*大模型SSD 长音频版-200（ssd_version = "200" + ssd_mode = 1）
版本说明：
*在 200 版本基础上，通过 ssd_mode 参数切换聚类模式
*聚类阈值为 5，能够有效抑制长音频聚类出 speaker 过多的问题
调用方式：
 
适用场景：
*长音频（3分钟以上）非会议场景
*需要减少说话人数量、合并相近音色的场景
*线下营销场景（如卖车、卖房，1位销售对多个顾客）
涉及链路： AUC 标准版 1.0 / 2.0（支持大模型 ssd 的链路均可）
*大模型SSD 长音频版-300（ssd_version = "300"）
版本说明：
*专为长音频会议场景优化
调用方式：
 
适用场景：
*长音频会议场景（推荐优先使用）
*线上会议、录音笔、录音卡、笔记 App 等多人说话场景
注意事项：
*短音频仍建议使用标准版本
*长音频（3分钟以上）非会议场景建议使用长音频版-200
涉及链路： AUC 标准版 1.0 / 2.0
*声纹匹配能力（voiceprints）
版本说明：
*在说话人分离基础上，支持声纹匹配
*用户先在声纹库中注册声纹，请求时带上声纹 ID，匹配成功的 speaker_id 会替换成对应声纹的名称（声纹注册方法详见文档：声纹注册/管理接口）
调用方式：
 
适用场景：
*需要识别具体说话人身份的场景（如客服质检中区分坐席与客户）
*会议中已知参会人身份，需要标注姓名的场景
限制：
*需开启说话人分离且 ssd_version 大于等于 "200"（200 和 300 版本均支持）
*一次识别请求最多支持 50 个声纹
*声纹需提前在声纹库中注册
*SAUC各版本详细说明
*流式大模型 SSD（说话人分离）
版本说明：
*流式链路使用大模型SSD，实时返回带说话人标识的识别结果
*支持两种流式输入模式：单向流式（nonstream）和双向流式二遍（async）
调用方式：
接口地址：
*单向流式：wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_nostream
*双向流式二遍：wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async（需开启 enable_nonstream=true）
 
*language 不指定或指定为 "zh-CN"（采用默认中英文模型）
*必须同时设置 show_utterances=true，流式结果的 utterances 分句中才会携带 speaker_id 说话人标识
分句机制：
*nonstream 链路未配置 end_window_size：默认使用语义分句，效果好
*nonstream 链路配置了 end_window_size 或双向流式二遍链路：采用 VAD 分句，definite=true 的句子返回时会根据说话人拆分，分成多个 definite=true 的句子
限制与影响：
*当前最多切分出 10 个说话人
*开启功能后尾包延迟会有上涨
*二遍链路尾包延迟增加 40-80ms
适用场景：
*实时语音转写场景（如实时会议字幕、直播字幕）
*需要低延迟说话人标注的流式场景
涉及链路： 豆包流式语音识别 1.0 / 2.0 上的流式输入模式链路
*短音频声纹识别（ssd_mode = 2）
*版本说明：
*面向双向流式二遍链路的短音频声纹识别能力，适用于一句话级别的人机对话场景
*音频中预期只有一个主说话人，通过传入声纹或声纹组，判定当前说话人属于哪个已注册声纹，满足"AI认主"等场景需求
*调用方式：
*接口地址：
*双向流式二遍：wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async
 
*voiceprints 只传一个元素且 group_id 不为空时，系统判定为使用声纹组匹配
*也可直接传入单个声纹 id（不传 group_id），进行 1:1 身份验证
*声纹需提前通过声纹管理接口注册并加入声纹组（声纹注册方法详见文档：声纹注册/管理接口）
*适用场景：
*人机对话场景下的 AI 认主（如 AI 玩具、智能音箱、手机助手、智能电视）
*车载座舱交互，注册主用户身份后区分说话人
*需要过滤背景人声、仅识别主说话人身份的近场/远场语音交互
*家庭成员声纹识别，根据不同说话人返回个性化内容
*限制：
*仅适用于短音频单说话人场景，不适用多说话人分离
*需开启双向流式二遍链路（enable_nonstream=true）
*voiceprints 数组仅支持一个元素（单个声纹或单个声纹组）
*声纹及声纹组需提前注册
*尾包延迟增加 40-80ms
*涉及链路： SAUC 双向流式二遍链路
*版本选择建议汇总
*按音频长度
*
*按场景类型
*
*影响说话人分离效果的因素
*声音质量：录音设备、采样率及环境噪声影响清晰度（高质量音频是基础）
*说话人特征：多个说话人音色相似会降低分离准确率
*插话/重叠：声音重叠的说话人当前无法区分；高频短插话容易分离不准
*有效语音时长太短：极短语音片段（<1秒）难以提取稳定的说话人特征
