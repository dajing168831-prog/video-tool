## 四、🩸 与「2.5 稳定性」直接相关的官方原文（2026-11-03 查实）

> 这一节是把散在各篇里的**稳定性口径**抽出来，出处都能逐字回查。

### 4.1 编辑任务输出会短 0.33–0.4 秒 —— 官方给了两个解法
`prompt-guide.md:695`《编辑前后时长不一致》：

> 视频编辑任务的输出比原视频短约 0.33 秒。
> 1. 切换为参考生成模式并指定输出时长；
> 2. **保持编辑任务时，将输入视频的帧数调整为 8n+1（n 为正整数），输出时长即可与原视频保持一致。**

`tutorial.md:2930` 同步口径：输出可能非整数秒、**误差不超过 0.4 秒**。
`api-create.md:494` 同上。

→ 我们的现状：`video_edit._EXTRA=0.5` + `_TAIL_TOL=0.45` 是**兜底**（少给的吃掉借款 / 尾段按实际长度收口）；
**官方给的正解 8n+1 我们没做**。这是「稳定」的第一号候选。

### 4.2 复杂任务效果不稳定 —— 官方要求拆步
`prompt-guide.md:738`：
> 一次生成同时承担多项参考、编辑要求时，整体效果不稳定。**将复杂任务拆解为多个简单任务，分多次生成或编辑完成，再通过后期剪辑整合。**

→ 复刻里「换人 + 换装 + 换场景 + 换风格」一次提交 = 复杂任务。要不要拆步，是产品决策。

### 4.3 角色对应错误 —— 按首次出场顺序上传
`prompt-guide.md:429`：
> 多人物视频中，角色与参考图片、音色或出场顺序发生错位……
> **按人物首次出场顺序上传参考素材，并同步调整提示词中的图片、音频编号，确保每个角色与参考素材一一对应。**

→ 我们现在的人物槽顺序 = 用户勾选顺序，**不是**出场顺序。这是多人复刻的一个明确风险点。

### 4.4 硬约束（写进代码的那些）
| 约束 | 出处 |
|---|---|
| 编辑任务 `ratio` 必须 `adaptive`、`duration` 必须 `-1` | `tutorial.md:36` / `:66` / `api-create.md:392` |
| 待编辑视频时长 `[4, 30]` s | `tutorial.md:38` / `api-create.md:509` |
| 编辑提示词必须含「编辑视频/增加/加上/删除/去掉/修改/替换/改成」之一 | `tutorial.md:67` |
| 显式 `edit`/`extend` → **同步**校验；`auto` → **异步**报错 | `tutorial.md:92` / `:100` |
| `seed` **2.5 不支持**（只 1.0 pro / pro fast） | `api-create.md:591` |
| 1080p 是 **10bit H.265/HEVC** | `tutorial.md:2858` |
| 输出帧率按 **24** 算 | `api-create.md:502` / `:524` |
| 参考图 1–30 张、宽高比 `[0.4,2.5]`、边长 `[300,6000]`、单张 ≤30MB | `api-create.md:177` |
| 参考视频 0–10 个、音频 0–10 个、总音频 ≤30s | `api-create.md:328` |
| 任务 ID 7 天、视频 URL 24 小时 | `tutorial.md:3087` |
| 个人账号 180 RPM / 并发 3 | `tutorial.md:3094` |

### 4.5 样片（Draft）模式 —— 官方自带的「先验后出」
`tutorial.md:2711`：`draft=true` 先出 480p 样片（按 480p 计费），确认后用 **Draft 任务 ID** 出正式片（**仅 1080p**）。
→ 对「稳定性」是现成手段：先花 480p 的钱验换人/构图/时长，再出正式片。
→ 但正式片只支持 1080p，**与我们当前 480p 试片策略不兼容**，属于产品取舍。
