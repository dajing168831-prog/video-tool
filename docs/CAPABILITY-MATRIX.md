## 二、判据口径（怎么算"像"，别凭感觉）

每条出片结果按这四个量具记，一次都不许省略：

| 量具 | 怎么量 | 判什么 |
|---|---|---|
| 人脸像素 | YuNet 在成片中点出目标人脸框，报 `宽×高` | 这个景别**最多**能给多少五官信息；< 60px 基本只能到性别/发型 |
| 参考图核对 | 上传素材的 sha1 与本地文件对比 | 发出去的是不是那张图（防"以为是新图其实发的旧图"） |
| 画面改动量 | 成片 vs 原片 PSNR | 判"到底改没改"；17–20 dB = 整体重绘，26+ 要怀疑只重编码 |
| 抽帧对照 | 同一秒抽源片/成片各一帧，并排看 | 人、物、场景、文字有没有真的变；有没有双胞胎、身份跳变 |

## 三.1 被忽略的一阶变量：**清晰度**（2026-10-22 查出的）

把 R5 和 R6 的**模型原生输出**拆开量，才看清"像不像"到底被什么决定：

| | 原生帧（模型真画出来的） | 成片（拉伸后） | 目标脸宽（成片 → 原生） |
|---|---|---|---|
| R5 `32711d24` | 496×864 | 720×1280 | 81px → **56px** |
| R6 `cf30ab9d` | 496×864 | 720×1280 | 48px → **33px** |

- 六次真机跑**全部是 480p**（`task.json` 里 `edit.resolution: '480p'`），
  而源片是 720×1280、2.0-mini 支持 720p、界面默认是「跟原片/自动」（= 720p）。
- 480p 竖屏的原生画面只有 496×864，再被拉回 720 宽 —— **拉伸 1.45×**，五官细节是插值出来的。
- 所以 R5「像」和 R6「不像」，第一顺位解释不是提示词里的"体型"两个字，
  而是**同一个词同时买来了像素**（主体被放大 → 脸 56px vs 33px）。
- 推论：在 480p 上继续调提示词，是在 33px 的脸里抠相似度，**杠杆用错了**。
  真正的杠杆是分辨率（720p 下同样的构图，原生脸约 48px）。
