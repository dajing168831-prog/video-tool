## 0. 目标判据（一句话）

**同一份作品，改一个字段，系统能自己算出「哪些产物失效、哪些可以复用」，并把这件事在花钱前说清楚。**

达到这句 = 2A 成立；达不到 = 只是把 `task.json` 换了个名字。

## 1. 六层结构（最小完整集）

| 层 | 职责 | 现在有什么 | 要新写什么 |
|---|---|---|---|
| **L1 作品文档** | 一份可重跑的配方：镜头 / 台词 / 角色 / 时间引用 / 素材引用 | `task.json` 的 recipe（只读快照） | `work.json`：可写、可 diff、可校验 |
| **L2 时间** | 台词锚到词，再投影成绝对时间窗口 | ASR 已返回**字级时间**（`chars:[{c,s,e}]`，`providers/asr.py:188-215`），但只用于烧字幕 | 词级锚定 + 投影（**不需要新模型**） |
| **L3 素材** | 每个产物 = 带签名的可复用对象 | 渲染目录里的一堆文件 + 隐式缓存 | `assets`：sha256 + 来源 + 依赖 |
| **L4 执行** | check → plan → build，三段分离 | `/plan` 已有雏形（与 render 共用决策） | Run 声明（targets / candidates / satisfy） |
| **L5 成片** | 画面轨 + 音轨 + 字幕轨 | `compose.py` 一次性拼装 | 轨道模型 + ffmpeg 执行器 |
| **L6 界面** | 用户只说"改什么" | 四个档位 + 六个保留开关 | 归位：档位降为内部策略，界面只留"改什么" |

## 2. 五个阶段

### P0 地基：文档 + 资产签名 + check/plan

- **做**：`work.json` schema；每个产物登记 sha256 与依赖；`check`（纯静态）、`plan`（列请求 + 列复用）。
- **验收（零成本，不调模型）**：
  1. 用现有 `89c228cc` 的 recipe 生成 `work.json`；
  2. 新旧两个 plan 的**段数 / 秒数**逐项相等；
  3. 同一份 work 连跑两次 plan，第二次的复用清单 = 全部。
- **风险**：这一步很容易做成"换名字"。判据就是 §0 那句话。

### P1 语义时间（路线二的核心差异）

- **做**：把台词按字级时间锚到原片；改词后重算段落窗口；把窗口投影到镜头。
- **验收（零成本）**：
  1. 改一句**等长**台词 → 字幕时间自动重排，画面复用清单不变；
  2. 改一句**不等长**台词 → 只有受影响的那几段失效，其余复用；
  3. 全程不调任何模型。
- 🩸 **必须写进产品的边界**：改词后**口型依赖的镜头必须重新生成**（hypit 的原话也是"改词要重新表演，改构图才复用素材"）。
  所以 plan 里每镜要标 `lip_dependent: true|false`：
  - `true`（露脸说话）→ 改词 ⇒ 该镜的视频也失效；
  - `false`（空镜/背影/产品特写）→ 改词 ⇒ 只换音频与字幕，画面复用。
  **不标这一位，就会承诺"改词不重画"然后翻车。**

### P2 轨道成片 ✅ 已完成（2026-10-22）

- **做**：把 `compose.py` 的一次性拼装换成轨道模型（视觉轨 / 音频轨 / 字幕轨），用 ffmpeg 执行。
- **验收**：同一组产物，新旧两版逐帧 PSNR、总时长、音轨采样数一致。
- **为什么值得做**：只有轨道模型，才能"改一处不重跑整条"；现在的 compose 是全量重拼。

**落地**：`backend/app/services/tracks.py`（模型 + 编译器 + 执行器）；`compose.py` 退成薄壳，
签名一个没动；旧实现原样冻结在 `backend/scripts/legacy_compose.py`，只当验收的尺子。
验收脚本 `backend/scripts/track_p2_check.py`，**26/26 通过**（零模型调用）：

| 项 | 结果 |
|---|---|
| 等价（配音+字幕 / 配音+底音+遮罩 / 只有原声 / 配音+定格补时长） | 四种情形**文件 sha256 完全相同**，PSNR = inf |
| 尺子自证（必须能判"不一样"） | 换 crf → 42.38 dB；去掉字幕 → 38.29 dB（有限值） |
| 多片段直接进画面轨 | 3 段拼出来与"原片整条"**逐帧一致**（1441 帧 / 2881813 采样，PSNR inf） |
| 轨道指纹 | 只改字幕→只有 captions 变；只改帧率/编码→只有 render 变；加底音→只有 audio 变 |

**两条实测出来的坑**（写进代码注释）：
1. 裁切不能既在输入 `-ss/-t` 又在滤镜 `trim` —— 两边都裁成品只剩碎片（3 段拼出 16 秒）；
2. 切点必须落在**帧边界**，按秒切会让相邻两段抢同一帧（多出 2 帧）。滤镜 `trim` 按帧时间戳切是干净的。

**这一步的真实收益**（别夸大）：
- 省的是**模型调用**（画面素材不用重新生成），不是 CPU —— 字幕烧在画面上，改字幕必然重编码；
- 画面轨现在能直接吃 N 段素材、只编一次码。

### P2.5 接线 ✅ 已完成（2026-10-22）

🩸 **这一轮抓到两条假红，都是尺子的问题，不是代码**：
① 拿 `len(intervals)` 当旧路径的段数 —— 区间边界会把时间轴切成更多基本段，
该用实际切出来的段数；② 给新旧成片设了 40 dB 门槛 —— 原片本身码率高，
单次 crf20 重编相对原片只有 28.5 dB，40 dB 是拍脑袋的门槛。改判"新路径比旧路径更接近原片"。

- **原来是什么**：单人契约 —— 1 个人物槽、1 张参考图、1 句定位词。换第二个人的唯一办法是再出一版。
- **现在**：`change.person_ids`（多选，上限 3）+ 人物槽 `person / person2 / person3`，
  一人一张图、一人一句「把@视频1中<这个人>替换为@图片N中的人物」；H3 侧一人一个
  `<Subject N>` 绑各自的 `<Picture N>`；范围闭环句（`_VOLC_SCOPE_CLOSURE`）统一收尾。
- **逐段分诊**：`vision_plan.targets_in` 返回这一段出现的所有被选者 —— 出现谁换谁，
  都不出现才留原片（保留原声时）；要重做口型时所有段都得重画。
- **上限 3 人的依据**：型号参考图张数（2.0 / H3 都是 ≤9 张，见 `model_specs.max_ref_images`），
  每人最多两张（大头照 + 全身照），再留三张给产品/场景/服装。
- **每人独立裁大头照**：`head_shot` 默认写 `subject_head.jpg`，多人会互相覆盖 →
  `video_edit.ref_plan` 按槽位指定输出名（`ref_person2_head.jpg`）。
- **兼容**：`person_id` 仍是第一项的别名；单人规格的提示词与缓存指纹与改动前**逐字一致**
  （96 组对照实测），历史出片的复用判定不受影响（`work._canon_change` 空字段不参与比较）。
- **验收** `backend/scripts/p9_check.py`，**36/36 通过**（零模型调用）；P4–P7 全部回归通过。
- **没验证的**：真机出片。能力表里只能写"代码已支持"，**不许写"已验证"**。
