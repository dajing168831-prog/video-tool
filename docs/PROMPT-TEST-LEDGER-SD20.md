## 四、铁律

1. **红 ≠ 模型一定失败，绿 ≠ 真机一定成功** —— 尺子只保证「指令没写错」，模型有随机性。
2. **空集不算通过**：每一组都必须报 `实际跑了几条 / 期望几条`，`0/0` 视为失败。
3. **一条红都不许留**：真发现红，先判是尺子假红还是编译器真错，**不许直接改尺子**。
4. **绿之前先证伪**：组合全绿还要再跑两道自证 ——
   **变量生效**（不同维度必须编出不同的句子，否则是编译器忽略参数造成的假绿）和
   **单变量消融**（每个开关单独打开必须真的改变输出，否则那个功能等于没有落点）。

### 5.3 纠正：我上一版把用例形状造错了

第一版 D5 用的是 `_sd_case(n=0, picks=())` —— 那条路径里 `person` 直接是 `False`、
`slots` 也是空的，等于在测「**没勾换人**」，跟生产不是一回事。
生产真形状是「勾了换人 + 传了人物图 + 盘点零人」：`slots` 里**有** `person`。

改正后编出来的是 **`严格编辑@视频1，将其中的**人物**替换为@图片1中的人物`** ——
**换人指令在**，只是宾语指认不到人。单人画面下这句完全正确；多人画面下才是病。
⇒ 「无盘点会白花一次编辑费」这个说法**不成立**，已撤回；
真正的问题见下条（点名被降级）。

### 5.4 「只换衣服/饰品/其他」不受盘点影响（2026-10-26 主人追问后实测）

盘点零人时，**不勾「换人」**的改动都走同一条老路径，提示词正常：

| 用户勾的 | 编出来 | 结论 |
|---|---|---|
| 只换装（全体，不点名） | `将其中的服装换成@图片2中的服装` | ✅ |
| 只换产品 + 点名哪一件 | `将其中的桌上的红色保温杯替换为@图片1中的产品` | ✅ |
| 只换场景 | `将其中的背景替换为@图片1中的场景` | ✅ |
| 只换风格（枚举） | `整体画面风格改成2D日漫风格` | ✅ |

原因：`_span_plan` 第一行就是「名单为空且没勾换人 → `return {}`」，
这几类**根本走不到盘点判断**。

**但点名换装被打回原形**（已修，见 D36 补）：

| 用户勾的 | 修前 | 修后 |

| 点名换装 P1 + 盘点零人 | `将其中的服装换成…` = **全体换装**，P1 这个点名丢了 | 出片前拦住，提示重新识别 |

| 换装**不点名**（全体）+ 盘点零人 | 整片一句 | **不变**（不许误伤） |

### 6.2 D10 抓到的两个「判据本身的问题」
