## 七、铁律（与 2.0 同一套）

1. **红 ≠ 模型一定失败，绿 ≠ 真机一定成功** —— 尺子只保证「指令没写错」。
2. **空集不算通过**：每组都报 `实际跑了几条 / 期望几条`。
3. **一条红都不许留**：先判是尺子假红还是编译器真错，**不许为了变绿直接改尺子**。
4. **绿之前先证伪**：变量生效 + 单变量消融两道自证都要过。
5. **规则不许跨型号搬**：2.0 的兜底包、`<主体N>`、全角括号，一条都不许进 2.5。

### 14.3 ① `【】` 是第三种"一符两用"

官方 `:867` 符号表：`【】` = **字幕**；我们模板 `:559-576` 的五段标题也用 `【】`。
`:880` 明令「同一符号不能承担两种职责」—— 用户文本里的 `【】` 会伪造段标题。
修法：自由文本清洗的字符集从 `[<>{}]` 扩到 `[<>{}【】]`。
⛔ 不动 `（）`：中文括号是日常标点，清掉会打断正常句子；`()` 只是"音乐"提示，
误留不会伪造结构。

### 14.4 ② 引号台词 → `{}`

`sd25-pe:141`：「用户只给出带引号的台词片段…只把该片段作为**可说出的原文**」；
`:867` 表：台词用 `{}`。⇒ 引号片段就是台词原文，进 2.5 模板必须换成 `{}`，
裸引号在最终 Prompt 里没有职责（`:867` 的表只有 `()` `<>` `{}` `【】` 四种）。

**取舍（记录在案）**：引号里如果是**非台词**（「把标题改成"限时优惠"」）也会被标成台词。
这是官方口径的必然结果 —— 要出现在画面上的文字官方规定用 `【】`（字幕），
而 `【】` 又是我们模板的段标题符号，只能清掉。宁可让它念出来，
也不留一个既不是台词、也不是字幕的裸引号。

先清 `{}` 再转换，不会套娃；上限 60 字与尺子 `_QUOTED_LINE` 一致。

### 14.5 ③ 尺子假红：「背景音乐」不是画面背景

`_bg_armed()` 只按分句判「句里有背景 + 有改动动词」，`背景音乐换成钢琴曲` 直接命中。
官方 `:867` 把**音乐**单列一类（`()`），`guide:231` 也把「音效、背景音乐（bgm）、对白」
和画面分开管。修法：判之前先把声音侧的 `背景音乐/背景配乐/背景音效/背景噪声/
背景噪音/背景音/背景声/背景bgm` 摘掉。
成对探针：同一句里换成**真换背景**必须照样响（防止修假红时把真红弄哑）。

### 20.2 真问题：带引号的台词没转 `{}`

`volc25._extend_prompt` 把用户 `content` **原样**插进模板句：

```python
f"随后，{c}。"
```

官方 `sd25-pe:141` 是硬要求：「用户只给出带引号的台词片段…**最终对白只能写成
`{你一个外人}`**」。主链路（`volc25_compile`）早就按 `_SPEECH_BEFORE` 转了，
**延长这条支线没有** —— 同一个产品里两种口径。

### 20.3 但不能照搬主链路的清洗

主链路把自由文本里的 `<>{}【】` 全清掉。**延长不能这么干**，因为
`sd25-pe:867` 的四个符号是**用户能合法写的**：

| 内容 | 符号 | 延长里该怎么处理 |
|---|---|---|
| 音乐 | `()` | 保留 |
| 音效 | `<>` | 保留 |
| 台词 | `{}` | 保留（用户手打的就是台词） |
| 字幕 | `【】` | 保留 |

差别在语义：主链路那个框是「补充说明」，用户不会在里面写符号；延长的
`content` 是「续出来的这段里发生什么」，写字幕/音效是正当用法。

### 20.4 修法（`volc25._clean_extend`，**2.5 专属文件**）

   没有说话动作的是名词引用（「把标题改成"限时优惠"」）→ 只去引号，**不标台词**
   （标了模型会把「限时优惠」念出来）。
2. **换行 → 逗号**：模板是整句插入，带换行会把句子切断。

`{}【】<>()` 一个都不清。

实测对照（同一批输入）：

## 二十二、延长做成加分项：预设续法（2026-10-28）

### 22.1 先想清楚「减分」到底减在哪

主人追问：「如果没有提示词编写能力的话，前端加的这些会不会是减分项？」

会。而且**不在 `@图片1` 上**——真正的门槛是**「后面发生什么」用户也写不出来**。
我们做的是让不会写提示词的人出片，结果延长又要他写一段剧情，等于把拆掉的门槛装回去。

### 22.2 官方给了答案：延长根本不该写新剧情

`sd25-pe:528`（延长章原文）：

> 只能延长**动作过程、反应、停顿或场景过渡**，例如让视线转移、呼吸变化、
> 拿取过程和进入后的反应自然展开。**不得新增人物、主线事件或故事结果**，
> 也不得用重复动作或空镜机械填满时间。

⇒ 用户不需要编剧情，只需要说"多留一会儿"。而且他要是真写了"女主突然哭了"，
恰好是官方禁止的那件事 —— **写了反而更容易跑偏**。

### 22.3 方案：让用户「选」，不让用户「写」

| | 以前 | 现在 |
|---|---|---|
| 输入 | 一个必须填的内容框 | **四个预设，默认选第一个** |
| 用户负担 | 要会写"续什么" | 点一下就提交 |
| 想自己写的人 | 只能写 | 第五个「我自己说」 |

四个预设**逐字对应官方列举的四个类别**，不是我们编的文案：

| key | 文案 |
|---|---|
| `action` | 让画面里正在进行的动作过程自然展开 |
| `reaction` | 让人物对刚才发生的反应自然展开 |
| `pause` | 让画面自然停顿片刻 |
| `scene` | 让场景过渡自然完成 |

## 二十三、延长下架：砍掉一个会主动偏离原片的功能（2026-10-28 主人拍板）

### 24.2 问题一：多人说话时句子被撑崩（真，已修）

`⑦ 2 人·配音两句各说` 的【目标素材职责】原文：

```

```


**根因**：`_sd25_who` / `_sd25_speaker_label` 的 `lab()` 把 `desc_zh` **整段**塞进说话人位，

- `:876`「台词语言使用：`语言 + 可选的地区变体或口音 + 表达方式 + **说话人** + {台词}`」
  —— 说话人槽是**一个名词短语**，不是整段外观
- `:876`「**多名说话人分别标注，不要只在开头统一声明**」
  —— 「`@音频1用于 A、B 的音色与台词`」正是被禁止的"开头统一声明"
- `:361`「`@音频1用于<角色或声音类型>的<音色、台词…>`」—— 模板本身就是一个角色一行
- `:218`「**一行只定义一个主体**…禁止把多个主体和多个素材压缩在同一句范围映射中」

**修法（只动 `app/services/models/volc25_compile.py`，三家共用层一个字节没碰）**：

| 改动 | 内容 |
|---|---|
| 新增 `_short_name()` | 先按共用口径 `_head_noun` 取；取不到就退**第一个分句** |
| `_sd25_speaker_label` / `_sd25_who.lab` | `_who(...)` 外面套 `_short_name(...)` |
| `_sd25_who(..., as_list=True)` | 返回列表而不是 `"、".join(...)` |
| 职责行 | **每个说话人一行** |

修后：

```
@音频1用于@图片1中的人物的音色与台词，不采用其中的无关声音内容。
```

### 24.7 判为「不违规」、被主人打回的一条（**已修**）

| 形态 | 我当时的判词 | 实际 |
|---|---|---|
| `@图片3用于体型偏胖的男子的服装的款式、颜色和材质` | 「官方 `:576` 模板是 `@图片X用于<目标主体>的<外观…>`，这里 `<目标主体>` = 「X的服装」，两个"的"是槽位填法的自然结果，**不是违规**」 | 主人：「**还来？**」—— 判「符合槽位」不等于「该这么写」 |

**错在哪**：我拿「结构上能解释得通」当免改理由。官方模板只规定"主体 + 的 + 属性"这**一层**关系，
没有规定主体内部还能再套一层「的」。官方自己的示例 `:600` 填的是
**「深灰色电动巡逻车的车身结构」** —— 主体「深灰色电动巡逻车」+ 一个"的" + 属性「车身结构」，
**只有一层**。我们写成「X的服装的款式」是两层，比官方示例多一层。

**修法**（`volc25_compile.py`，只动 2.5 自己的编译器）：

```

修后：@图片3用于体型偏胖的男子的服装款式、颜色和材质，…
```

`<目标主体>` = 「X的服装」、`<材质…>` = 「款式、颜色和材质」，中间那个"的"由模板自带，
主体里不能再留一个。`_DUTY_ROLE["wardrobe"]` 在 `edit_spec.py` 里三家共用，**没动**。

**副作用（已一并修）**：`ruler_sd25._t12_split` 按「最后一个"的"」切主语。写法少一层"的"之后
「服装」跑到属性串开头，主语被切回人 → 和同一人的人像图算成**同一主体**，T12 会误报
（已用探针实测复现）。修法是属性串以「服装」**直接**接属性词时把「服装」并回主语；
后面跟「和/、/与」时**不合并** —— 那是 `:184` 白名单里服装与配饰并列的写法，主体仍是人。
合并条件写宽了会把 `_T12C_BAD`（真·同主体）弄哑，实测踩到过一次。

## 二十六、E5 那条红：出片前的闸已经拦住（不是产品缺陷，2026-10-28）

### 26.1 现象

穷举 572 份里只剩 1 份红：`E5 盘点没给描述（2 人）` → `C3 多人画面必须指认是哪一位`。
正文那句是「只把**人物**替换为@图片1中的人物」—— 画面里两个人，宾语没指认，模型会换错人。

### 26.2 但生产发不出这份 Prompt

`video_edit.require_identifiable_volc25`（单人换人走 `_gate_single_frame`）在
「同框的人**既没有唯一方位、也没有能区分的描述**」时直接抛 `EditError`，**钱还没花**。
`identifiability_check.py --model volc25` 把这件事穷举了：

```
2/3/5 人 × 3 种方位形态（全同方位 / 全 unknown / 没有 position 字段）
        × 2 种描述形态（全同描述 / 无描述）= 48 组
→ 18 组会写出重复指代，18/18 全部被闸拦住
→ ✅ 所有重复指代的形态都在出片前被闸拦住 —— 这是设计，不是缺陷
```

穷举脚本 `dump25_exhaustive.py` 是**直调编译器**的，不经过这道闸，所以它会看见这份红。

### 26.3 落地的防复发措施

`dump25_exhaustive.py` 的 `INDEX.tsv` 新增第 6 列 **「闸」**：这份产出的输入在生产里发不发得出去。
当前 572 份：

| 列 | 数量 | 说明 |
|---|---|---|
| 红 ≠ 0 | **1** | 就是 E5 那条，且闸拦 |
| 闸拦 | **2** | `E5 盘点没给描述（2 人）`、`E5 5 人同框` |

> 🩸 `E5 5 人同框` 被闸拦是**夹具问题**，不是产品拦太严：夹具 `_POS_CYCLE` 只有 4 个方位，
> 5 个人循环回第 1 个 ⇒ 第 5 人与第 1 人的 (方位, 描述) 完全相同。生产里 5 个人各占一格不会这样。
